# magpie-plugin-codar

给 [magpie](https://github.com/yetone/magpie) 用的 **Codar（科搭）** 插件——把科搭的模型接进 magpie 当供应商用，替你每天签到，并在账号卡片上显示点数。

## 做了什么

| 钩子 | 作用 |
|---|---|
| `config` / `provider` | 增加一个 `codar` 供应商，带科搭的模型表（17 个：`auto` 路由 + DeepSeek、GLM、GPT、Claude 各系）。表是从 App 自己的目录里取的，登录后还会从 `GET /v1/codar/models` 刷新。 |
| `auth.methods` | 两种登录：「读取本机科搭令牌」（keyless，插件自己去读 `~/.codar/config.json`，只读）和「科搭访问令牌」粘贴。 |
| `auth.checkin` | 每天 `POST /v1/daily-sign` 一次。返回能区分「本次领到」和「今天已经领过」，并给出距下次可领的时间——含 `until`（magpie ≥ 0.1.1795）：科搭是滚动 24 小时，magpie 便正好到点再问，而不是中午前每 30 分钟重问一遍。说不出多久（厂商没给、给了 0、超出年 9999，或超过一周——这个窗口滚动 24 小时，31 年不是它能给出的下次可领时刻）时给 30 分钟的保质期：宿主把「done 且无 `until`」当成当天已结算，滚动窗口就会漏掉下一次可领。 |
| `auth.usage` | 点数（`/v1/gettoken`：通用点数 + Agent 点数）、今天签到状态、还在进行中的免费模型活动及其到期时间。三处读取并行发出。点数同时作为钱包读数报出，路由页便有这个账号的数目可看，而不是「剩余额度未知」。 |
| `chat.headers` | 只对 `codar` 自己的请求发和桌面端一样的 `User-Agent`（这个钩子对所有供应商的请求都会被调用，插件按供应商 id 自筛）。 |

聊天请求由 magpie 直接发到科搭的网关 `https://api.claw.speedai.com/v1`：多数模型走 OpenAI 兼容协议，Claude 系走 Anthropic Messages 协议——和桌面端侧车用的是同样两条。

## 令牌从哪来

科搭登录后是一把 JWT，存在它自己的配置文件里：

- macOS / Linux：`~/.codar/config.json`
- Windows：`%USERPROFILE%\.codar\config.json`（按 App 的平台约定推断；只在 macOS 上实测过）
- 设了 `CODAR_HOME` 时是 `$CODAR_HOME/config.json`：App 认这个变量（`codar config path` 会报出它用的路径），插件也认

取 `provider.speedai.token` 的值，粘到 magpie 要 key 的地方：

```bash
python3 -c 'import json,os;print(json.load(open(os.path.expanduser("~/.codar/config.json")))["provider"]["speedai"]["token"])'
```

**更省事的办法**：登录时选「读取本机科搭令牌」，插件自己去读这个文件（只读、不写），不用手工复制。它认 `provider.speedai.token`，并在交出去之前检查令牌里有没有账号名、有没有过期——有问题会直接说原因，而不是存一个用不了的值。

令牌里带着账号名和过期时间（App 最后一次登录后 7 天）。过期后插件不会去调接口，而是直接提示重新登录——打开一次科搭让它自己续期，再重新登录插件一次即可。

## 安装

```bash
magpie plugin add "$PWD"       # 尚未发布；先从这个目录装
# magpie plugin add github:MisonL/magpie-plugin-codar   # 发布之后
magpie plugin login codar     # 选「读取本机科搭令牌」，或「科搭访问令牌」粘贴
```

然后在 magpie 里选一个 `codar` 模型，到 设置 → 额度 → 预热与签到 → 插件 里打开它的签到开关。

## 这个插件不做什么

- **不领取免费模型活动。** `POST /api/codar/activities/free-model/claim` 是一次性的活动领取，不是每日签到；插件只负责报告正在进行的活动。
- **不读写桌面端的配置文件**——「读取本机科搭令牌」登录时会读一次 `~/.codar/config.json`（只读），令牌存进 magpie 自己的 `plugin-auth.json`；任何时候都不写那个文件。
- **不换算价格。** 科搭的目录是人民币/百万 token，magpie 的金额栏是美元，所以插件自己不报价格，而不是编一个汇率。magpie 仍会按 models.dev 上模型厂商的标价给模型定价；`claude-opus-5-kiro` 这种带厂商后缀的 id 在 models.dev 里没有，但 magpie 会按厂商应答里的 `served` 模型（`claude-opus-5`）计价。想改哪个，在 magpie 里给模型单独设价格即可。
- **不把厂商的推理档位映射成 magpie 的变体。** 目录里每个模型的档位都在（`reasoning.levels`），但一档的含义是一串写请求体的字段（`set`/`omit`），由桌面端自己套上去；magpie 的 variants 只是档位名，请求里转发客户端自己的档位。插件没有办法说「这一档对请求做什么」，列出来就等于承诺 magpie 按厂商的方式套不出来的档位——所以模型只带 `reasoning: true`，不带 variants。

## 说明

- 请求头和 App 保持一致，按链路分：账号接口、活动接口、模型目录用 Node 的默认 `User-Agent`（App 的 Electron 主进程读这些，它自己不加 UA），对话用 Go HTTP 客户端的（App 的 Go 侧车就是这么发的）。除此之外不加任何东西。
- `chat.headers` 钩子会被 magpie 用在每个供应商的请求上（不是只用在科搭上），插件按供应商 id 判断，只改 `codar` 自己的请求，别家的流量原样不动。
- 供应商默认叫「科搭 Codar」，供应商级的 `api`/`npm` 默认指向科搭的网关：这几项都只在还没有值时写，重启不会覆盖你自己设的（在 magpie 里改过名、或把 `api` 指向自建代理，都保留）。单个模型的设置同理，合并按字段深入到嵌套对象：只设 `provider.api` 不会丢掉目录里的 `provider.npm`，只设 `limit.output` 也留着上下文窗口；每个对象都有的那几个键（`__proto__`、`constructor`、`prototype`）永远不参与合并——模型没有叫这些名字的字段，**叫这些名字的模型条目也一并丢掉**：`models["__proto__"] = …` 写的是这张模型表的原型，不是一条模型。厂商实时目录里 id 叫这些名字的记录同样丢掉（宿主拿到那份列表的下一步是同一句方括号赋值），改名或种进来的 id 不会变成 magpie 所建模型表的原型。供应商槽位装的是数组时当作没有，而不是往里写（数组的索引键会落进你的配置里）。你设的地址两条路径按同一条规则写下：config 条目和实时列表给每个模型写的基址都裁掉首尾空白和尾随斜杠，只剩空白的值不算值（落到网关）——magpie 拼请求是把路径接在基址后面原样写出去的，基址留着 `.../v1//` 发出去的就是 `.../v1//chat/completions`。实时目录刷新也认同一个地址：厂商目录带回来的每个模型都写在你的 `api` 上（模型自己设了地址就用它的），不写科搭网关——magpie 取基址时模型级 URL 压过供应商级，写死网关会让你的代理在第一次刷新成功后失效。厂商自己的模型条目以厂商的目录为准；你在 magpie 界面上给单个模型设的名字、价格、推理档位存在 magpie 自己的设置里，在这张模型表之外，刷新不会动它们。
- 写不出来的时刻一律省略，不凑一个错的：窗口的 `resetsAt` 和「N 后可再领」文案，在厂商给的数缺失、为 0、非有限（`1e999` 读成 `Infinity`）或超出年 9999 时都不报——magpie 会把时间 0 画成 1970-01-01，而不是当成「没说」。签到窗口多一道自己的界：它的一天滚动 24 小时，超过一周的等待不是这个窗口能给出的下次可领时刻，签到按「没说」处理；活动的结束时间是真的日期，日历能写到哪就报到哪。签到的 `until` 是唯一不能省的那项：宿主把「done 且无 `until`」当成当天已结算，用不上的等待按上面说的落到 30 分钟保质期。
- 状态与余额按厂商自己的客户端读：签到状态认 `data` 为布尔，或 `isSigned`/`signed`/`hasSigned`/`has_signed` 任一（只认真正的布尔）；余额认 `token`/`remaining_points`/`points`/`balance` 与 `agent_token`/`agentToken`/`agent_points`/`agentPoints`；负数读数当作没说——宿主会把钱包读数夹到 0，报负数等于卡片上两个互相矛盾的说法。应答体里的 `code` 是 200 以外的数字时，按那个客户端的读法就是拒绝：点数读取带着这个码报错，而不是报「0 点」；被拒的签到状态不画这一行，而不是画成「现在可以领」；被拒的免费活动列表即使还带着 `data` 也不画。码关的另一面：没带 `code` 的应答不算拒绝——厂商客户端就是这么放行的（它的活动接口今天就不带 code），所以签到应答没有 code 时按它说的成功算，除非应答自己写着 `success: false`；而签到应答上的这个 `success: false` 无论有没有 code 都作准——`code:200` 配 `success:false` 就是「HTTP 层说好、厂商说不」，以厂商为准。这个旗标只在签到应答上读：签到状态和活动列表按那个客户端自己的关卡读，它只看 code，所以那里没有拒绝码的 `success: false` 照它的数据画——和 App 自己画的一样。唯一的例外是厂商自己那句「今天已领过」：`400` 配「24小时内仅可领取一次」、再带个 `success:false`，仍是那个客户端的「今天已领」，读成失败会让 magpie 当天每 30 分钟重问一遍，而卡片一直写「签到失败」。签到的话——包括区分「本次领到」和「今天已领过」的那句——按客户端的读法，取 `message`/`msg`/`error`/`detail` 与 `data` 下同样四个字段里第一个有字的；点数的拒绝文案也读这同一组拼写。厂商把余额包在 `data` 里时，也从 `data` 读——它的客户端就是先拆这一层。签到的 credit 是两处余额在两次读数之间的增量之和（厂商只说「签到领取点数奖励」，没说落在哪一处），减少的那一处（App 花掉的）不从奖励里扣。
- 令牌过期时插件不会去问厂商：模型列表原样保留（`catalog.mjs` 那份），但**不标回退**——宿主只在真去问了才发现拿不到时才标；卡片上会提示重新登录。令牌的 `exp` 按厂商客户端读：数字，或说得出数字的字符串；声明里根本没有 `exp` 的令牌不会被插件判成过期——那个客户端把这种令牌叫「unknown」，交给厂商去答。
- `GET /v1/codar/models` 拿不到时，供应商保留 `catalog.mjs` 里内嵌的那份，magpie 会把列表标成回退。回退列表里 Claude 系同样走 Anthropic 协议：每个模型自带自己的 SDK，而不只是供应商的默认值。厂商**答了**的列表不算回退，空列表也不算：厂商说这个账号没有模型，就是没有；而每条记录都被插件剔掉（id 用不了）的那份是「读不出来的列表」，仍然回退。
- 你自己加到这个供应商里的模型条目（内嵌目录里没有的 id）在实时目录刷新后仍然保留；厂商自己的模型以厂商的目录为准。不是普通对象的模型条目（null、字符串、数组）会被丢掉，而不是原样带过去：宿主用一张 `Promise.all` 把每个供应商的模型表一次建完，其中一个这样的条目就会抛异常——整份供应商列表都建不出来，不只是丢掉这一条。
- 模型的回复上限用厂商自己的数：目录里每个模型都带 `max_tokens.maximum`（今天 17 个里有 16 个；`gpt-5.6-sol` 没说，0 就是「没说」），作为模型的 `limit.output` 报出去。magpie 会把要得比它多的请求降到这个数（网关的 `maxoutput.go`），所以 agent 要超了上限时拿到的是降下来的请求，而不是厂商的拒绝。内嵌在 `catalog.mjs` 里的那份是上次生成时厂商的答案，也就是目录拿不到时的回退，尺寸可能落在实时目录后面；能取到实时目录时以实时为准。
- 科搭的免费模型对每个模型限定 3 个并发请求（实测：同时发 4 个，第 4 个收到 429 `concurrent_limit_exceeded`，「Too many concurrent requests」）。插件的 auth 钩子声明了 3，magpie 会把每个账号超过 3 个的请求排队，而不是让它们撞上厂商的限流；供应商设置里可以调高。
  厂商目前哪个接口都不公布这个数——`/v1/codar/models` 没有、`/api/pricing` 没有、429 的响应体里只有 `retry-after`——所以 3 是量出来的。哪天目录里带上 `max_concurrency`（整数；小数会被忽略），模型钩子会读到它，下次建供应商信息时就用新数，不用等插件发版。
- 点数同时作为一扇带 `balance` 的窗口报出（magpie #3950）：只有 `aside` 行的卡片对路由什么都没说，magpie 就在账号旁边写「剩余额度未知」。钱包读数让它变成已知，直接给出还剩多少，也不编造百分比。读不懂窗口 `balance` 的旧版 magpie 只把它当文字行显示、照旧说未知；两种版本都不会出错。钱包带的是通用点数；只报了 `agent_token` 的应答（今天两处都报）会把 Agent 数写在卡片文案里，但路由没有可以依的钱包读数。
- 免费模型活动按厂商 App 自己的判据画——`free_until` 未到、`remaining_quota` 没花光——不看它不读的 `status` 字段。它是 `aside`——用完了只是这些模型回到按点数计费，账号不停——`amount`/`limit` 只在厂商给了总额（`user_quota_limit`）**且**还剩多少也读得出时才带：只有那时才是一对真数。有总额但读不出剩余的说总额（「免费使用中，共 N」），而不是当成「不限量」；剩余比总额还大的照说剩余，只有两个数都没有的才显示「不限量」。
- 每日签到是一行文字，不是百分比：签到不是会用完的额度，插件不报 `used`，magpie 就照文字显示。
- 「读取本机科搭令牌」认 `CODAR_HOME`：App 认它（`codar config path` 会答 `$CODAR_HOME/config.json`），所以插件读的就是 App 写的那份文件；没设时用上面的主目录。
- 科搭自己的网关出过短时故障（模型目录对所有客户端都 500，桌面端也一样）；这种情况下插件保留卡片上的点数，只丢掉读不到的部分。

## 开发

```bash
node --test                        # 整个测试套件，不联网
bun test                           # magpie 真正加载插件的运行时
node scripts/catalog.mjs --check   # catalog.mjs 还是厂商现在说的那份吗？
node scripts/catalog.mjs           # 按本机已登录的 App 重新生成
```

测试会桩掉 `fetch`，不连 SpeedAI。CI 在 Node 18–24、Bun（Linux/macOS/Windows）、以及 Windows/macOS 的 Node 上跑同一套——插件会读主目录下的文件，平台差异就在那里暴露。

`catalog.mjs` 是回退列表，由厂商自己的目录生成后提交；运行时看不出它已经过时，所以卡片上的尺寸和实时网关对不上时跑一次 `--check`，厂商加模型时重新生成。它按和登录一样的方式读 App 的令牌，任何情况下都不打印。

生成器用插件自己的 `catalogOf` 来造记录，回退文件和实时列表因此按同一套规则读（厂商把尺寸写成字符串，两边都当尺寸；名字两边都是卡片能显示的一行）。`--check` 逐字段比记录，键顺序换过、注释改过都不算漂移。退出码把两种失败分开：0 是没动静，1 是记录变了、该重新生成，2 是厂商或文件读不出来——取数失败时它什么都不写，而不是把回退清空；厂商这次答 0 个模型的也不写进去。它要有已登录的 App，是本机命令，不是 CI 里的一步。
